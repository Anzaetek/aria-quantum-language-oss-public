## Rules that apply to every phase

* **Work in a worktree**, never in the main checkout while a CI run reads it.
  Rebase on `origin/main` before landing; other sessions land on main daily.
* **A10 holds for every new check:** each new test or gate is shown red by a
  deliberate mutation before it is trusted, and the mutation is recorded.
* **RAM rule:** every heavy run under
  `OMEGA_HOSTGATE=/tmp/akilles-hostgate.ledger OMEGA_HOSTGATE_MODE=enforce
  omega-hostgate run --host-bytes 40G`. Full `./ci.sh` runs detached
  (`setsid nohup`), never as a tracked background task.
* **Brutal review is a gate, not a courtesy.** Every phase ends with an
  adversarial review by a reviewer that did not write the code (model ladder:
  brutal review → fable). The reviewer is told to try to break the work —
  re-run claimed numbers, apply mutations, look for vacuous tests and for
  claims the code does not support — and to report evidence, not opinion.
  Findings are fixed or rebutted in writing before landing.
* **Regular CI:** a full CI run on `origin/main` before the first phase
  (baseline), and a full CI on the landed tip after every phase. The CI
  profile is `ARIA_QISKIT_XCHECK=1 ARIA_BRIDGE_XCHECK=1 ARIA_NWAY=1
  ARIA_QEC_XCHECK=1 ARIA_LEAN=1 ARIA_CUDA=1` — every gate this box can run.
  A phase is not done while its CI is red or still running.

## Phase 3 — the stabilizer targets, in a concrete model (§5 #4 residual)

`verification/Verification/Backend/StabilizerExpectation.lean` has three
targets over free axioms. Reset's four were discharged by building a concrete
model (`proofs/lean4/QuantumProofs/ResetModel.lean`, 401 lines) and proving
the targets there; this phase does the same for the stabilizer file, under the
pinned Mathlib in `proofs/lean4`.

The model, `proofs/lean4/QuantumProofs/StabilizerModel.lean`:

* **Paulis as symplectic vectors.** An `n`-qubit Pauli up to phase is
  `(x, z) : (Fin n → ZMod 2) × (Fin n → ZMod 2)`; the commutation form is
  `ω((x,z),(x',z')) = Σ x·z' + z·x'` over `ZMod 2`. Anticommuting means
  `ω = 1`.
* **A stabilizer group** is given by `n` generators whose symplectic vectors
  are linearly independent and pairwise `ω = 0` (an isotropic subspace of
  dimension `n`), plus a sign per generator.
* **The state** is any unit vector `ψ : EuclideanSpace ℂ (Fin n → Bool)` that
  is a `+1` eigenvector of every signed generator, with Paulis acting as
  concrete matrices (`X`, `Z` bit-flip / phase on the basis), and
  `expectation ψ P := ⟪ψ, P ψ⟫.re`.

Targets, in order of difficulty:

1. **T3 `echelon_reduction_complete`** — *done 2026-10-08 in
   `StabilizerModel.lean` by the elimination invariant rather than the
   dimension route below; see STATUS §5 #4.* Pure symplectic linear algebra: if
   `ω(p, g) = 0` for every generator `g` of an `n`-dimensional isotropic
   subspace `W` of `(ZMod 2)^{2n}`, then `p ∈ W`. Proof route: `ω` is
   nondegenerate, so `dim W + dim W^⊥ = 2n`; `W ⊆ W^⊥` and `dim W = n` give
   `W = W^⊥`. `reducesToIdentity` becomes `p ∈ Submodule.span gens`.
2. **T1 `expectation_trichotomy`** — on the state: anticommuting with some
   generator gives `⟨P⟩ = 0` (`⟨ψ|P|ψ⟩ = ⟨ψ|Pg|ψ⟩ = −⟨ψ|gP|ψ⟩ = −⟨P⟩`);
   `+P` in the signed group gives `1`; `−P` gives `−1`.
3. **T2 `zero_only_when_anticommuting`** — from T3 (commuting ⇒ in the group
   up to sign) and T1 (in the group ⇒ `±1 ≠ 0`). The sign bookkeeping of a
   product of signed generators is the part most likely to need care; if it
   resists, T2 is stated and proved for the generators' span with the sign
   carried explicitly, and the gap is recorded rather than papered over.

Requirements:

* Every target gets an **instantiation witness** (Bell or a 3-qubit GHZ
  stabilizer state) so no premise is vacuous — the defect class
  `autoImplicit` already caused once in this tree.
* `#print axioms` shows only `propext`, `Classical.choice`, `Quot.sound`;
  `ci.sh`'s `ARIA_LEAN=1` stage gains a `lean_axioms "Stabilizer model
  theorems" N` line with the exact count.
* **Mutations to show red** (changing a definition, not a proof): `ω` with
  `x·z'` only; a generator set that is dependent; the sign dropped from the
  `−P` case.
* The abstract file's three `sorry`s stay — they are the specification — and
  STATUS §5 #4 records which targets now hold in the model.

## Phase 4 — the emulator comparison (§5 #17), plan and first lane

§5 #17 asks for comparison against the alternatives, not more correctness
oracles. This phase writes the full plan and builds the **dense statevector
lane on akilles**; MPS and Metal lanes follow in a later plan.

Plan document (`docs/EMULATOR-COMPARISON.md`), fixed before any number:

* **Per lane, the yardstick and why.** Dense CPU: qulacs (the fastest
  widely-used CPU statevector) and Qiskit Aer (already installed, the common
  reference). Dense GPU: cuStateVec via `qiskit-aer-gpu` or `qsimcirq`'s
  cuStateVec backend, whichever installs against CUDA 12.9 here. MPS: quimb
  (and ITensor if a Julia toolchain is acceptable). Metal: no common
  yardstick exists; andromeda decides.
* **Workload set, fixed:** QFT, random brickwork (`depth = n`), GHZ, QAOA
  MaxCut p=2 on a 3-regular graph — at `n ∈ {16, 20, 24, 26, 28}` for dense
  (28 = 4 GiB complex128, inside the 40 GB rule), each emitted once as
  QASM2 so every engine reads the identical circuit.
* **What is timed:** full-state evolution only (no sampling, no transpile,
  no file I/O), median of 5 after one warm-up, plus peak RSS of the
  process. Our side runs through `omega-run` exactly as a user would.
* **Correctness travels with every row:** each engine's state is compared
  to the reference by fidelity; a row whose fidelity is below `1 − 1e-10` is
  published as a FAIL, not as a time. Precision is stated per engine
  (complex128 everywhere it is available; a complex64 row is labelled).
* **Capability table, both directions:** what each engine can express that
  the others cannot — certificates as bounds, mid-circuit Reset policy,
  qudits on our side; whatever the competitors have that we lack.
* **Named hardware and versions** in every table header.

Implementation, `tools/emulator_compare/`:

* `workloads.py` emits the QASM2 files; `run_engine.py <engine> <qasm>`
  runs one engine in a subprocess and prints one JSON line (time, RSS,
  state hash and the statevector to a temp file); `compare.py` runs the
  matrix under hostgate, checks fidelities, writes a markdown table and a
  JSON file.
* A missing engine is a registered skip, never a silent omission; a
  harness that compared zero rows exits non-zero.
* **Mutations to show red:** corrupt one engine's state by one phase → its
  row reads FAIL; delete an engine from the venv → a skip is reported.
